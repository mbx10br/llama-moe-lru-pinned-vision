# Native bundles: pinned vision, sleep and protected-prefix selection

Two independent, pinned generations are available. Apply exactly one bundle to
its matching upstream commit; do not stack them.

| Generation | Upstream base | Manifest |
| --- | --- | --- |
| Original tested integration | `620d2225cc436ab0b001e3200e590e3b286ef9ab` | [manifest.json](manifest.json) |
| Latest source refresh | `39da130fcd1b6ca47d3c0522a40eccff41ea3dfb` | [manifest-39da130f.json](manifest-39da130f.json) |

The newer [39da130f bundle](39da130f-sleep-grid-dual-prefix.patch) retains upstream
expert SLRU and checkpoint invalidation, includes the private restore contracts,
and registers the prefix-selection test with CMake. Its manifest records the
qualification status separately; historical measurements below remain historical.

Verify the newer generation without loading a model:

```sh
python3 tools/verify_native_patch.py --source /path/to/llama.cpp \
  --manifest manifest-39da130f.json --compile-policy
```

For that build, substitute the full `39da130f...` revision and matching patch in
the commands below. The registered `test-server-prefix-selection` target can
also be built and run alongside `test-server-component`.

## Original generation

Apply `620d2225-sleep-grid-dual-prefix.patch` to **exactly** llama.cpp commit
`620d2225cc436ab0b001e3200e590e3b286ef9ab`. That upstream revision already has
the MiB-based MoE expert cache. This bundle is an alternative generation to
the historical slot-based patches in the repository root; do not stack them.

The patch exports the ten changed/new source files from the deployed, built
candidate. `manifest.json` records the patch digest and before/after file hashes.
No model weights, binary checkpoints, generated bytecode or personal deployment
settings are part of it.

## Included changes

- Selective immutable vision weights in pinned host RAM with strict CUDA
  execution, while ordinary model/expert host mappings can remain pageable.
- Optional expert host registration, disabled unless explicitly requested.
- Bounded prompt-cache preservation across compatible same-process sleep/wake.
- Experimental four-checkpoint interior anchors, behind `ORNITH_CHECKPOINT_GRID`.
- Opt-in slot restore policy comparing usable active, RAM and disk states,
  including hybrid/recurrent checkpoint eligibility and transactional preservation.
- Model-free component assertions and a standalone native selection test.

The new `/props` feature markers are `supports_prefix_restore_if_better` and
`supports_prefix_preserve_active`. The protected-prefix controller must require
both before using its opt-in private restore options. Unpatched restore requests
retain the previous behavior. The saved state format is unchanged by this bundle.

## Apply and build

Use a separate checkout; do not overwrite a live model runtime:

```sh
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
git checkout 620d2225cc436ab0b001e3200e590e3b286ef9ab
git apply --check /path/to/this/repository/patches/llama.cpp/620d2225-sleep-grid-dual-prefix.patch
git apply /path/to/this/repository/patches/llama.cpp/620d2225-sleep-grid-dual-prefix.patch
cmake -S . -B build -DGGML_CUDA=ON -DLLAMA_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --target llama-server test-server-component -j 12
./build/bin/test-server-component
c++ -std=c++17 -O2 -Wall -Wextra -Werror tests/test-server-prefix-selection.cpp -o /tmp/test-prefix-selection
/tmp/test-prefix-selection
```

The measured laptop build used Linux, CUDA 13.1, SM86 and 12 build jobs at nice
15. Select the correct CUDA architecture and build resource limits for your own
machine. These commands are source integration instructions, not a claim that
all operating systems, GPUs or newer upstream commits have been qualified.

For a CPU-only check of patch application, exact file digests and the standalone
selection policy, see `tools/verify_native_patch.py` in the project root.

## Validation and limits

The native candidate previously passed 41 component cases / 172 assertions and
the standalone selector. Real-model tests exercised both protected bases,
advanced-state preservation, sleep, interface switching and complete process
restart. The published patch is checked against the pinned source again when
packaged. GPU timing numbers in the benchmark report describe those recorded
tests; publishing does not rerun inference on a user's busy machine.

The checkpoint grid remains experimental: strict numerical comparisons found
later-token differences in some edge cases. Consult the existing cache-return
evidence and README. Full 100K/130K conversations, every multimodal case and
universal bitwise output parity are not established by these short tests.
